Purchase order approval inbox

Running in development, built to replace My Inbox

  • SAP CAP (Node.js)
  • Fiori / UI5
  • SAP Event Mesh
  • RAP OData
  • Work Zone notifications

Problem. Approvers handled purchase order flexible-workflow approvals in the standard My Inbox and needed an inbox that works well on desktop and mobile, with the same features.

What I built. An event-driven CAP and Fiori app in SAP Build Work Zone. S/4HANA business events reach the app through SAP Event Mesh, approvers are alerted through Work Zone notifications, and approve or reject decisions go back through a RAP-based OData service. I proved each layer step by step: an ABAP approval program first, then the OData service, then the CAP app.

Design choice. The app keeps only temporary PO data (header and line items) and removes it once a PO is decided, so S/4HANA stays the single source of truth.

AI agent for purchase order analysis

Proof of concept

  • AI agent
  • MCP
  • SAP CAP
  • React
  • S/4HANA OData

Idea. Let a buyer or approver ask questions about purchase orders in plain language instead of running reports and transactions one by one.

What I built. An AI agent that reaches SAP purchase order data through MCP (Model Context Protocol) tools, with a SAP CAP back end and a React front end. The agent picks the right tool, pulls the PO data and returns an analysis the user can act on.

Why it matters. It connects classic S/4HANA data with modern AI agents, which is where SAP projects are heading.

Credit limit approval app

Deployed to development and production

  • SAP CAP
  • Fiori / UI5
  • BTP Cloud Foundry
  • Destinations
  • BAPIs

Problem. Credit limit changes needed a request and approval flow with the customer's real numbers in front of the approver.

What I built. A CAP and Fiori app on BTP that reads customer and ledger balance data live from S/4HANA through destinations. Requests are raised per credit segment, since one customer can hold several.

Detail I'm proud of. Credit insurance details are shown per sales organisation from an admin configuration. Only approvers can change them, and every change end-dates the old entry and creates a new one through standard BAPIs, so the full history stays in S/4HANA.

RF carton scanning for production consumption

Built in sandbox, transported to development

  • EWM RF framework
  • ABAP
  • Function modules
  • RF customizing

Problem. Warehouse staff consuming stock against manufacturing orders on handheld scanners needed to count by carton, including partial and damaged cartons.

What I built. Custom logic inside the standard EWM RF transaction for consumption by manufacturing order. My PBO and PAI function modules wrap the standard ones, so the standard flow keeps working while the screen adds carton scan counts and handles fractional and damaged cartons.

Row-level data separation in a RAP app

Design and implementation in progress

  • RAP managed
  • CDS
  • DCL access control
  • Instance authorization

Problem. Two business entities share one RAP app for bundle material headers and items, and neither may see the other's data.

Approach. CDS access controls (DCL) filter what each user can read, and instance authorization in the behavior definition blocks changes to records outside the user's entity.
